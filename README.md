# 💬 FemboyChat

**Тёплый real-time мессенджер: веб, PWA и десктопное приложение для Windows.** Вход без пароля, каналы с комментариями, боты и ИИ-собеседники, всё живое без перезагрузки страницы.

> В этом файле описано только то, что действительно работает в коде. Всё, чего ещё нет, вынесено в раздел «В планах» — там честно.

---

## ✨ Что умеет

**Вход и профиль**

- Вход без пароля: e-mail + `@юзернейм`, подтверждение одноразовым кодом.
- Порядковый номер аккаунта (`#14`) и уникальный юзернейм.
- Профиль с аватаркой, обложкой, описанием и статусом.
- Пин-код на вход в приложение.
- Список своих сессий и устройств с возможностью отозвать лишние.

**Чаты**

- Личные переписки, группы, каналы-вещания, боты, «Избранное».
- Приглашения по ссылке — с ограничением по числу переходов и сроку жизни.
- Блокировка пользователей: заблокированный физически не может прислать сообщение, это проверяется на сервере.
- Закрепление, папки, отметки о прочтении, «печатает…», статусы онлайн.

**Сообщения**

- Ответы, цитирование фрагмента, пересылка, редактирование, удаление, реакции.
- Комментарии к постам в каналах и счётчик просмотров.
- Опросы, стикеры, форматирование (`**жирный**`, `*курсив*`, `` `код` ``, `~~зачёркнутый~~`, ссылки).
- Исчезающие сообщения: таймер живёт на сервере, чистка идёт по расписанию, а не «пока вкладка открыта».
- Поиск по всем своим сообщениям сразу, а не только по открытому чату.
- Выделение нескольких сообщений и групповые действия.

**Медиа**

- Фото, видео, файлы и голосовые сообщения.
- Вложения лежат в приватном хранилище и отдаются по подписанным ссылкам: чужой файл не открыть по прямому адресу.
- Полноэкранный просмотр, drag & drop, вставка из буфера.

**ИИ и боты**

- Встроенные собеседники FemboyAI и KisKis отвечают прямо в чате, ответ печатается потоком.
- Своя студия ботов: можно создать собственного бота с характером и командами.

**Оформление и мелочи**

- Темы, акцентные цвета, обои, размер текста, скругление бабблов.
- Свой набор иконок и звуковых схем.
- Push-уведомления в вебе и PWA.
- Свайпы, длинный тап и прочие жесты на телефоне.

## 🚀 Быстрый старт

```bash
npm install
npm run dev        # http://localhost:5173
```

Без ключей Supabase приложение поднимется в демо-режиме: данные лежат в браузере, код подтверждения показывается прямо на экране, почта не нужна.

Чтобы посмотреть real-time в демо-режиме, откройте две вкладки, заведите в них **разные** аккаунты (сессия у каждой вкладки своя) и напишите друг другу — вкладки синхронизируются между собой.

Остальные команды:

```bash
npm run build      # прод-сборка в dist/
npm run preview    # предпросмотр прод-сборки
npm run typecheck  # проверка типов (tsc --noEmit)
npm run verify     # headless-тест ядра на LocalBackend
```

> `npm run build` **не** проверяет типы. Перед пушем гоняйте `npm run typecheck` отдельно, иначе неиспользованный импорт уронит сборку в проде.

## 🏗️ Архитектура

Стек: **Vite + React + TypeScript + Tailwind CSS + Zustand**.

Ключевая идея — **сменный бэкенд** за единым интерфейсом (`src/lib/backend/types.ts`). Оба адаптера реализуют один и тот же контракт, поэтому UI не знает, где на самом деле лежат данные.

| Режим | Когда включается | Что даёт |
| --- | --- | --- |
| `LocalBackend` | локальная разработка без ключей Supabase | Всё живёт в браузере: `localStorage` и `sessionStorage` для данных и сессии, `BroadcastChannel` — для обмена между вкладками. Код подтверждения показывается в интерфейсе. |
| `SupabaseBackend` | заданы `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`, либо это прод-сборка | Настоящая почта с кодом, синхронизация между устройствами, Realtime, серверные правила доступа. |

```
src/
├─ components/        UI: лендинг, авторизация, приложение, настройки
├─ lib/
│  ├─ backend/        адаптеры: types, local, supabase, выбор в index
│  ├─ appearance.ts   тема и акцент через CSS-переменные
│  └─ icons, sound, viewport, util…
├─ store/useStore.ts  Zustand-хранилище и обработка real-time событий
└─ types.ts           доменные типы

scripts/               сборка иконок и графики установщика
src-tauri/             десктопная оболочка
supabase/              схема, миграции, edge-функции
```

## 🗄️ Supabase

Схема **не** живёт в этом README. Источник правды:

- `supabase/schema.sql` — снимок текущей схемы целиком;
- `supabase/migrations/` — миграции по порядку;
- `supabase/functions/` — edge-функции (пуши, ИИ, превью ссылок).

Любое изменение схемы делается **миграцией** и коммитится в репозиторий. Правки руками через веб-редактор ломают воспроизводимость.

Про политики доступа: ни одна из них не написана как «разрешить всем». Доступ к чату определяется членством, к сообщению — доступом к его чату, к вложению — доступом к чату, в котором оно отправлено. Если добавляете свою политику, не пишите `using (true)` — это открывает базу наружу через публичный ключ.

Для локальной работы скопируйте `.env.example` в `.env` и подставьте `Project URL` и `anon public key`. Анонимный ключ по своей природе публичный и попадает в бандл — это нормально, всё остальное закрывается правилами доступа на стороне базы.

## 🖥️ Десктопное приложение

Windows-приложение собирается на **Tauri v2**, установщик — NSIS, полностью свой по оформлению.

```bash
npm run desktop:icons   # иконки + графика и скрипт установщика
npm run desktop:build   # сборка .exe
```

Нюансы, о которых лучше знать заранее:

- Для графики установщика нужен пакет `sharp` и файл `icon.png` в корне.
- Приложение **не подписано** сертификатом, поэтому Windows SmartScreen при первом запуске покажет предупреждение. Нажмите «Подробнее» → «Выполнить в любом случае». Это не обходится ничем, кроме покупки сертификата подписи кода.
- **Автообновления нет.** Новая версия ставится поверх старой вручную.
- Собрать `.exe` можно и в облаке: workflow `Build Windows EXE` во вкладке Actions, запускается кнопкой, результат забирается из артефактов прогона.

Подробности — в `DESKTOP.md`.
